# مقدمة

تُبقي **dynamic-sticky-sidebar** الشريط الجانبي ظاهرًا أثناء تمرير الصفحة، حتى لو كان أطول من الشاشة وكانت الترويسة فوقه تغيّر حجمها باستمرار.

## المشكلة {#the-problem}

تعمل `position: sticky; top: 80px` العادية جيدًا إلى أن يحدث أحد الأمور التالية:

- **الشريط الجانبي أطول من منفذ العرض (viewport).** يُثبَّت أعلاه، ولا يمكن الوصول إلى جزئه السفلي إلا عند نهاية الصفحة.
- **الترويسة تختفي وتظهر.** كثير من المواقع تُخفي الترويسة (أو صف تنقّل ثانيًا) بانزلاقها عند التمرير لأسفل، وتعيدها عند التمرير لأعلى. قيمة `top` الثابتة إما أن تترك فراغًا أو تجعل الشريط ينزلق تحت الترويسة.
- **الترويسة يتغيّر ارتفاعها.** تُغلَق اللافتات، وتتمدد أشرطة البحث، وتنطوي الترويسات إلى وضع مصغّر.

الحلول المعتادة إما أن تستمع إلى حدث `scroll` وتضبط `transform` أو `top` في كل إطار، مما يسبب اهتزازًا وتأخرًا، وإما أن تحتاج إلى إزاحات مضبوطة يدويًا لكل حالة من حالات الترويسة.

## ما الذي تفعله هذه المكتبة {#what-this-library-does}

- **تثبيت لاصق في الاتجاهين.** عند التمرير لأسفل، يتحرك الشريط الجانبي الطويل مع المحتوى حتى تبلغ حافته **السفلية** منفذ العرض، ثم يلتصق. وعند التمرير لأعلى، يعود حتى تبلغ حافته **العلوية** الترويسة، ثم يلتصق. أما الشريط القصير فيبقى ببساطة مثبّتًا تحت الترويسة.
- **تتبّع حي للترويسة.** تمرّر عنصر الترويسة (أو عناصرها)، فيستقر الشريط الجانبي تحت أدنى حافة ظاهرة لها. ويتبعها إطارًا بإطار أثناء انزلاقها أو انطوائها أو تغيّر حجمها.
- **الأولوية للسلوك الأصلي.** خاصية `position: sticky` في المتصفح هي التي تعالج كل إطار تمرير. ولا تغيّر JS قيود التثبيت (`top` و`bottom` وهامشًا) إلا حين ينعكس اتجاه التمرير أو تتحرك الترويسة. راجع [كيف تعمل](./how-it-works.md).

## الحزم {#packages}

هناك حزمة npm واحدة بثلاث نقاط دخول:

| الاستيراد | استخدمه لـ |
| --- | --- |
| `dynamic-sticky-sidebar` | النواة المستقلة عن أي إطار عمل: [`stickySidebar()`](../frameworks/vanilla.md) |
| `dynamic-sticky-sidebar/react` | [الخطاف `useStickySidebar` والمكوّن `<StickySidebar>`](../frameworks/react.md) |
| `dynamic-sticky-sidebar/vue` | [دالة composable والموجّه `v-sticky-sidebar` والإضافة (plugin)](../frameworks/vue.md) |

React (الإصدار 16.8 فأحدث) وVue (الإصدار 3.3 فأحدث) اعتماديتان نظيرتان (peer dependencies) اختياريتان. ثبّت فقط ما تستخدمه.

تأتي الأنواع (types) مع الحزمة، وتُحَل مع الإعدادين `moduleResolution: "bundler"` / `"node16"` ومع الإعداد الأقدم `"node"`.

## حجم الحزمة {#bundle-size}

قيست الأحجام على البناء المنشور بعد تصغيره مع `NODE_ENV=production` كما تفعل أداة التجميع لديك. تتضمن مدخلات React وVue النواةَ.

| المدخل | بعد التصغير | gzip | brotli |
| --- | --- | --- | --- |
| `dynamic-sticky-sidebar` | 3.4 kB | 1.8 kB | 1.6 kB |
| `dynamic-sticky-sidebar/react` | 4.6 kB | 2.2 kB | 2.0 kB |
| `dynamic-sticky-sidebar/vue` | 4.2 kB | 2.1 kB | 1.9 kB |
| بناء CDN عبر `<script>` | 3.8 kB | 2.0 kB | 1.8 kB |

- **بلا اعتماديات.** لا تُستخدم React وVue إلا في نقاط الدخول الخاصة بهما.
- **تُحذف تحذيرات التطوير في الإنتاج.** تلميحات وحدة التحكم المذكورة في [استكشاف الأخطاء وإصلاحها](./troubleshooting.md) محاطة بالشرط `process.env.NODE_ENV !== 'production'`، لذا تزيلها Vite وwebpack وNext.js وNuxt من حِزم الإنتاج. بناء التطوير للنواة أكبر بنحو 0.2 kB (gzip).
- **قابلة لهزّ الشجرة (tree-shaking).** الحزمة معلَّمة بـ `sideEffects: false`، ومكوّن React موسوم بأنه نقي (pure)، لذا تُحذف التصديرات غير المستخدمة.

شغّل `pnpm size` في المستودع لإعادة إنتاج هذه الأرقام.

## دعم المتصفحات {#browser-support}

أي متصفح يدعم `position: sticky` و`ResizeObserver` و`MutationObserver`، وهذا يشمل كل المتصفحات الحديثة دائمة التحديث. وتستهدف بناءات ESM/CJS وبناء CDN عبر `<script>` معيار ES2020.

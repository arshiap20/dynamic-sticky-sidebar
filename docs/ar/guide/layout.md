# متطلبات التخطيط

تُبنى المكتبة على `position: sticky`، لذا تنطبق قواعد التثبيت المعتادة، إضافةً إلى قاعدة أخرى تخص العنصر الأب للشريط الجانبي.

## الموصى به: الشبكة (grid) {#recommended-grid}

```css
.layout {
    display: grid;
    grid-template-columns: 280px 1fr;
    align-items: start;
}
```

مع أب من نوع **grid** أو **flex صفّي**، يعمل اتجاها التمرير كلاهما بالتثبيت الأصلي للمتصفح. لا تعدّل JS القيود إلا حين يتغيّر الاتجاه، لذا لا يتأخر الشريط الجانبي عن التمرير أبدًا.

ويعمل flex الصفّي بالطريقة نفسها:

```css
.layout {
    display: flex;
    flex-direction: row; /* or row-reverse */
    align-items: flex-start;
}
.layout > aside {
    flex: 0 0 280px;
}
```

## يجب ألّا يتمدد الشريط الجانبي {#the-sidebar-must-not-stretch}

تتمدد عناصر grid وflex افتراضيًا إلى ارتفاع الصف. والشريط الجانبي المتمدد يكون بطول عمود المحتوى، فلا يبقى للتثبيت مجال للحركة ولا يحدث شيء. استخدم أحد الخيارين:

- `align-items: start` (grid) / `align-items: flex-start` (flex) على العنصر الأب، أو
- `align-self: start` على الشريط الجانبي نفسه.

ويجب أن يكون العنصر الأب نفسه بطول المحتوى المُمرَّر. وهذا هو الوضع الافتراضي حين يتشارك الشريط الجانبي والمحتوى الرئيسي الصف نفسه.

## التخطيط الكتلي (الحل البديل) {#block-layout-fallback}

إذا كان العنصر الأب كتلة عادية، كأن يكون الشريط الجانبي ملفوفًا داخل `<div>` عمودي متمدد، فإن المكتبة تظل تعمل:

- التمرير **لأسفل** أصلي، كما في وضع grid؛
- التمرير **لأعلى** يستخدم قيمة `top` تحسبها JS، وقد تتأخر إطارًا واحدًا عن التمرير السريع.

في بناءات التطوير، تسجّل المكتبة هذا مرة واحدة في وحدة التحكم:

```
[dynamic-sticky-sidebar] parent is not grid / row-flex, so scrolling up uses a JS fallback that can lag a frame. …
```

لإصلاح ذلك، أعطِ **الأب المباشر** للشريط الجانبي `display: grid` (تكفي شبكة بعمود واحد):

```css
.sidebar-column {
    display: grid;
    align-items: start;
}
```

## خاصية overflow على العناصر الأسلاف {#overflow-on-ancestors}

كما في أي عنصر لاصق، فإن أي عنصر سلف يقع بين الشريط الجانبي وحاوية التمرير ويحمل `overflow: hidden | auto | scroll` يصبح هو حاوية التثبيت، فيتعطل الالتصاق بالصفحة. ومن المتسببين الشائعين أغلفة الصفحة التي تستخدم `overflow-x: hidden` لإخفاء الفيض الأفقي.

- استخدم `overflow: clip` (أو `overflow-x: clip`) بدلًا من `hidden`؛ فهي تقصّ المحتوى دون إنشاء حاوية تمرير.
- إذا كان الشريط الجانبي يعيش فعلًا داخل لوحة قابلة للتمرير، فمرّر تلك اللوحة في الخيار [`scroller`](../api/README.md#scroller).

## الشاشات الصغيرة {#small-screens}

على الجوال، يُرصّ الشريط الجانبي عادةً فوق المحتوى أو تحته، ولا ينبغي أن يكون لاصقًا. استخدم `media` حتى لا تعمل المكتبة إلا حين يكون التخطيط بعمودين:

```js
stickySidebar('#sidebar', {
    header: '.site-header',
    media: '(min-width: 768px)',
});
```

حين يتوقف الاستعلام عن المطابقة، تزيل المكتبة مستمعيها وتعيد الأنماط المضمّنة (inline) الأصلية للشريط الجانبي. ثم تبدأ من جديد حين يطابق الاستعلام.

## الأنماط التي تعدّلها المكتبة {#styles-the-library-touches}

أثناء عملها، تكتب المكتبة الأنماط المضمّنة التالية على عنصر الشريط الجانبي:

| الخاصية | السبب |
| --- | --- |
| `position` | تُضبط على `sticky` إن لم تكن كذلك أصلًا |
| `top`، `bottom` | قيود التثبيت |
| `margin-top`، `margin-bottom` | تُبقي الشريط الجانبي في مكانه أثناء "تحريره" بين حالتي التثبيت |
| `align-self` | تُضبط على `flex-end` أثناء التمرير لأعلى في وضع grid/flex |
| `overflow-anchor` | تُضبط على `none` كي لا يتعارض تثبيت التمرير (scroll anchoring) مع التعديلات |

تُحفظ القيم المضمّنة الأصلية حين تبدأ المكتبة، وتُستعاد عند `destroy()` أو حين يتوقف `media` عن المطابقة. احتفظ بتباعداتك الخاصة في ورقة أنماط أو صنف (class)، لا في أنماط مضمّنة تغيّرها أثناء عمل المكتبة.
